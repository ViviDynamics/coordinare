{{- if .Values.devenvCache.enabled }}

Performer environment cache: claim {{ include "coordinare.devenvClaim" . }} in namespace {{ include "coordinare.performerNamespace" . }}.
{{- if eq (include "coordinare.devenvMode" .) "create" }}
This release creates it, and it needs a StorageClass that supports
ReadWriteMany (RWX). Check that it binds before the first dispatch:

  kubectl get pvc -n {{ include "coordinare.performerNamespace" . }} {{ include "coordinare.devenvClaim" . }}

  STATUS Bound:   the claim is ready.
  STATUS Pending: no RWX-capable StorageClass is serving it. The bootstrap
                  performer and every consumer that mounts this claim WAIT,
                  and no symphony gets its environment until it binds.

To find an RWX-capable class, list them with `kubectl get storageclass` and
check each provisioner's documentation for ReadWriteMany (NFS, CephFS, EFS,
Azure Files, and Longhorn with RWX are common). Then set
devenvCache.storageClassName to it and upgrade. If you have none, opt out with
devenvCache.enabled: false, which runs every performer with a cold cache.
{{- if not (has "ReadWriteMany" .Values.devenvCache.accessModes) }}

WARNING: devenvCache.accessModes does not include ReadWriteMany. Performers on
other nodes cannot mount a ReadWriteOnce claim, so their bootstrap and cache
reads fail or stay Pending.
{{- end }}
