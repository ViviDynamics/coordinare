# Dependency Licence Audit

**Feature**: 142-license-and-legal-posture | **Audit date**: 2026-08-28
**Enforces**: FR-018, FR-019, FR-019a, FR-020 | **Contract**: [accepted-licenses.md](./contracts/accepted-licenses.md)

## How this was produced

Generated by walking the transitive runtime closure of each distributed project from its `uv.lock` with stdlib `tomllib`, then reading each package's licence from installed metadata via stdlib `importlib.metadata`. No new dependency was added to audit dependencies.

The generator imports its derivation helpers directly from `tests/unit/test_142_license_and_legal_posture.py`, so this document and the automated check cannot disagree. Regenerating after a dependency change is therefore the correct response to a check failure.

Licence field precedence: `License-Expression` (PEP 639 SPDX), then a short free-text `License`, then a `License ::` classifier. Free-text values longer than 40 characters are refused, because in practice they are the whole licence text pasted into a header rather than an identifier. Short values that name an *arrangement* rather than a licence (`Dual License`) are refused for the same reason: they carry no identifier. A package left unclassifiable that way is resolved by reading the licence text it actually ships and recording the result in the test module's `VERIFIED_LICENSES` table, which reports its metadata field as `verified`. `python-dateutil` is the only such package. Inferring an expression by OR-ing a package's several `License ::` classifiers was considered and rejected: `orjson` publishes Apache, MIT and MPL-2.0 classifiers while its true expression is `MPL-2.0 AND (Apache-2.0 OR MIT)`, so the inference would drop a real MPL obligation. Because `OR` resolves to its most permissive operand, guessing here fails open.

**Scope**: what coordinare distributes and runs. Development-only dependencies are excluded, since they are never conveyed to a recipient and so carry no distribution obligation.

## Tier 2: permitted, each with a written rationale

Weak-copyleft packages. Per the contract, each needs its own rationale recording that it is redistributed unmodified and how it is consumed. An exception without a rationale fails the check, which is what stops this list decaying into a second allowlist nobody has thought about.

### `certifi` 2026.1.4

- **Licence**: `MPL-2.0` (via `License`)
- **Consumed as**: import
- **Distributed via**: pypi_dependency
- **Rationale**: MPL-2.0 is file-level copyleft. We do not modify any MPL file, so the obligation is notice only.

### `orjson` 3.11.7

- **Licence**: `MPL-2.0 AND (Apache-2.0 OR MIT)` (via `License-Expression`)
- **Consumed as**: import
- **Distributed via**: pypi_dependency
- **Rationale**: Published as `MPL-2.0 AND (Apache-2.0 OR MIT)`. The conjunction means the MPL-2.0 obligation applies to the MPL-licensed files regardless of the permissive half, so this is judged as MPL-2.0 rather than laundered through the Apache/MIT option. MPL-2.0 is file-level copyleft, we modify no file, so the obligation is notice only.

### `psycopg` 3.3.2

- **Licence**: `LGPL-3.0-only` (via `License-Expression`)
- **Consumed as**: import
- **Distributed via**: pypi_dependency
- **Rationale**: Reaches us through the declared runtime dependency `langgraph-checkpoint-postgres`. Imported as a Python library, which is dynamic linking by any reasonable reading, installed unmodified from PyPI, and replaceable by the user with their own build. This is the case LGPL was written to permit.

### `semgrep`

- **Licence**: `LGPL-2.1-or-later`
- **Consumed as**: subprocess
- **Distributed via**: container_image
- **Rationale**: Installed by `agent/performer/Dockerfile.full` and invoked as a separate process by `src/coordinare/services/security_scanner.py`. Two independent questions, and conflating them is the usual error. As a *combined work*: invoking a separate executable is aggregation, not linking, so LGPL-2.1's obligations do not reach coordinare's own source. As *distribution*: the image does bundle the binary, which carries notice and source-availability obligations for semgrep itself. Both are satisfied trivially, since semgrep is published on PyPI and GitHub and we do not modify it.

## Standing limitations

1. **This audit is a point-in-time snapshot.** A package can relicense between releases, which is why enforcement lives in a test that runs on every change rather than in this document alone.
2. **Platform-conditional packages are unverified** on the platform where the check runs. See above.
3. **Licence metadata is self-reported** by each package. A package that misdeclares its licence would be misclassified here. Verifying every upstream against its actual licence text is out of proportion to the risk for a permissive-heavy tree, and is recorded as an accepted limitation rather than silently assumed away.
