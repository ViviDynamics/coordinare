# Reviewed Environment Manifest Implementation Plan

Issue #351. Spec: [spec.md](spec.md). User authorized unattended delivery using ship-issue.

## Scope

Replace environment-specific discovery, rendering, persona and consumer activation with
one independently reviewed generic contract. Preserve safe writes, frozen provenance,
Docker/Kubernetes execution and existing attempt budgets. No new dependencies.

## Architecture and interfaces

Put shared types and execution in `packages/service_inference/src/coordinare_service_inference/environment/`.
This existing wheel is installed in both daemon and performer images.

- `models.py`: `EnvironmentManifest`, `Requirement`, `Command`, `Activation`, `Service`,
  `CoverageAssessment`, `CheckResult`, `VerificationReport`; strict validation and canonical
  SHA256 `EnvironmentManifest.digest()`. `Command` uses `id`, `argv: list[str]`, `cwd`
  (default `{repo}`), `env: dict[str,str]`, `depends_on: list[str]`, `timeout_seconds`
  (default 180), `required: bool` (default true), `scope: list[str]` (empty means all).
  Shell semantics require explicit `argv: ["bash", "-c", "..."]`.
- Manifest fields: `schema_version: Literal[1]`, `symphony_name`, `source_commit`,
  `inputs: dict[str,str]` (path to content SHA256), `requirements: list[Requirement]`,
  `install: list[Command]`, `checks: list[Command]`, `activation: Activation`,
  `services: list[Service]`, `empty_reason: str | None`, `policy_version: Literal["351-v1"]`.
  Requirement: `id`, `description`, `source` (repo path), `checks: list[str]`, `required`.
  Activation: `path: list[str]`, `env: dict[str,str]`; root substitutions are only
  `{cache}`, `{repo}`, `{scratch}`. Env references use `${NAME}` resolved at runtime,
  never interpolated as shell syntax. Service: `id`, `start: Command`, `health: Command`,
  `stop: Command`, optional `init: Command`, `required: bool`.
- `runner.py`: `run_manifest(manifest, *, cache, repo, scratch, install=False, scope="")`
  returns VerificationReport and executes argv in isolated child processes. Track each
  exit/timeout/prerequisite; bounded output, redact supplied secrets; own process groups
  for cancellation. Service state lives in scratch, health gates checks, teardown always.
- `render.py`: `render_activate(manifest, *, cache_mount_path)` and
  `render_verify(manifest, *, cache_mount_path)` generate trusted text. Verification
  embeds canonical manifest data and calls shared runner from the trusted image, not
  cache scripts. Consumer activation is declarative and idempotent.
- `src/coordinare/services/environment_discovery.py`: bounded read-only GitHub snapshot
  discovery via existing `ChatJson` async messages->str seam. JSON tool loop supports
  `read_file` and `list_files` only. `discover_and_review(*, symphony_name, commit,
  paths, fetch, chat, declared_services=None)` returns `(EnvironmentManifest,
  CoverageAssessment)`. A separate conversation reviews the candidate with independent
  reads of snapshot data; validates exact digest, citations, complete inspections.
  Raise `EnvironmentDiscoveryError` for missing model, malformed response or any hold.
- `GitHubService.get_repository_paths(org, repo, *, ref)` returns complete blob-path
  inventory via the recursive Git tree REST API; truncated inventory refuses.
- Daemon `EnvCacheState`: persist `environment_manifest` and `environment_assessment`
  as optional dicts, clear before discovery, store only accepted pair. Existing trusted
  rendered text is generated from that pair. Source head SHA participates in invalidation
  to catch newly added files; unchanged head costs no model calls. Old cache has no pair
  and cannot pass readiness. Preserve atomic trust/provenance publication.
- Payload rides `metadata.environment_manifest` and `metadata.environment_assessment`
  with `metadata.environment_manifest_digest`. The performer validates those before
  install; bypasses legacy service inference/recipes for the new contract. Prose and
  workflow bootstrap install declared actions, then run deterministic checks. Consumer
  uses trusted manifest activation and generic checks, never Ruby marker inference.

## Constraints and bounds

Follow spec FR-001..023 and SC-001..009. No ecosystem catalog in the new active path.
256 KiB manifest/assessment, 256 reads, 256 KiB per file, 4 MiB aggregate source,
100,000 inventory entries, 120-second discovery/review, 180-second default checks,
30-second cleanup, 4 KiB output/check and 256 KiB/attempt. Preserve outer deadline and
attempt accounting. Reject unsupported capabilities; no silent old-path fallback.
Independent assessment is required even when no extra dependencies are found. Required
checks must run; an agent cannot waive them. Trusted verifier output is generated by the
parent runner from collected exit codes, child output is data and cannot forge reports.

  following ship-issue with required checks. Retain task evidence in checkpoint.

## Review focus

1. Trust output cannot be forged by stdout from installed binaries.
2. No accepted review can be reused for a revised manifest/source snapshot.
3. Kubernetes trusted verifier and consumer materialization remain compatible.
4. Services and source requirements cannot be silently skipped in clean verification.
5. All failure and cleanup paths hold closed with bounded restart-persistent budgets.
