# Docker workspace storage (issue 327)

## Investigation

- `init_files.configure_containers` generates starter RW binds from the XDG data directory's `workspaces` to `/workspace` and `artifacts` to `/artifacts`. It sets `TMPDIR=/workspace` and, since 322, `NODE_COMPILE_CACHE=/var/cache/node-compile-cache` (container-local). No other cache or capture mount is generated by init.
- `DockerRuntime.start_ephemeral` delegates to `services/performer_lifecycle.py`, which formats every `VolumeMount.host_path` into `-v source:target:mode`. `docker_setup.smoke_container` independently does the same. The model only declares host paths, although a bare relative path accidentally acts as a Docker volume name. Explicit named-volume support must distinguish host paths for daemon file guards and routing.
- `workspace.WorkspaceManager.prepare` skips local clones for HTTP/Docker; its cleanup only removes daemon subprocess workspaces. Performer `workspace.py` uses temporary directories and removes its own clones. Docker orphan reconciliation reaps containers, not workspace files. No daemon reader needs `/workspace`.
- `/artifacts` has no built-in daemon file reader or performer writer; retain the existing host mount for operator integrations. Per-job reports and QA evidence pass through the performer result/events and uploads. QA capture directories use `mkdtemp`, are consumed/deleted by performer postprocessing, and follow TMPDIR.
- `__main__._build_http_performer_services` optionally adds a RW host `performer_log_dir` bind at `/var/log/performer`. Hermes and workflow adapters write diagnostic artifacts there. Dashboard live logs use service buffers/runtime logs, not these files. Keep operator-visible diagnostic binds.
- Optional `LITELLM_PROXY_CAPTURE_DIR` is not generated by init. Proxy/shim/Claude capture writers operate inside the performer (including chmod 0700); no daemon capture-file reader was found. Existing explicit capture binds must remain host-visible for operators.
- `services/env_cache.py` dynamically adds `env_cache_root/<symphony>` at `/devenv/<name>`, RW for bootstrap and RO for consumers. The daemon seeds manifest/activate/verify/service scripts, checks population, walks provenance, verifies locally, and manages cache state on the host. The daemon bootstrap idle-reaper stops containers; no separate host workspace/cache tree reaper was found in the current source. These are not disposable workspace caches and cannot move without a new cache API/verifier design.
- `http_performer_service` receives transcripts via `GET /jobs/{id}?transcript_after=N`; `run_transcript` writes them on the daemon. `DockerRuntime.iter_logs` streams `docker logs` into daemon-owned `run_log` files. Dashboard history/runs/timeline/run_logs read those daemon files. State, env-cache state, and attempts are daemon-owned. Keep all outside performer mounts.
- Host-file security guards in config, mounted_file, routing_config_service, and HTTP transcript setup enumerate endpoint host paths. Named volumes must be excluded, never interpreted as paths.
- Removal documented in `docs/releases.md` is `install.sh --uninstall`, not `bin/uninstall` (the latter removes a checkout service). Installer currently preserves XDG config/data and only `--purge` removes legacy `~/.coordinare`.

## Design and acceptance

Add mutually exclusive `volume_name` and `host_path` mount sources, validated Docker names and unchanged RO/RW modes. New starter configs mount `coordinare-workspaces-<12 hex SHA256 of resolved config directory>` at `/workspace`. This isolates installs/configurations on the same Docker engine, is stable across force-init, and requires no root host writes. Docker creates it lazily. Retain `/artifacts` as a host bind.

Force-init migrates only the starter's `/workspace` bind, retaining its mode and unrelated settings/mounts. Existing configs keep their current mount until init is explicitly rerun. Existing named mounts, custom container targets and non-starter endpoints remain untouched. A custom host source at the starter target `/workspace` is still a workspace bind and migrates. No old files are copied or deleted automatically.

Installer derives the same name for the default config directory or `--config-dir`. It inspects and offers to remove only that managed volume; `--yes`/COORDINARE_YES permits removal without a terminal. Decline/no terminal preserves it. Missing Docker or removal failure warns without preventing tool uninstall. Custom volume names remain operator-managed.

Smoke asserts no UID-0 files/directories under its data root before cleanup, retains 322 fallback cleanup, and removes its temporary named volume after stopping containers. Unit tests cover migration, source validation, both launch paths, guards, uninstall consent/failure and smoke assertion.

## Remaining ownership TODOs

Default init does not configure diagnostic capture/log writers and `/artifacts` has no automatic writer. Do not chmod diagnostic captures broadly: they can contain sensitive prompts. Env-bootstrap toolchains in the retained host env-cache can also be root-owned. Daemon-created seed files alone do not solve ownership of apt/toolchain installs.
