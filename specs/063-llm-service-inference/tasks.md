## Phase 3 — Per-run cache invalidation

- [x] T019 Persist last-successful `services.json` alongside the env-cache artifact set so the next build can read its `cache_inputs`. Implemented `load_prior_manifest(cache_dir)` in `src/coordinare/services/service_inference/cache_key.py` reading `<cache_dir>/services/services.json` and round-tripping through `ServicesManifest.model_validate_json`; returns `None` on missing file, invalid JSON, or schema mismatch so callers fall back cleanly. Manual-override + retry-loop writers (T005/T013) already drop the file at this path. Unit tests in `tests/unit/services/test_service_inference_cache_key.py::test_load_prior_manifest_*` cover the four return paths.
- [x] T020 Modify env-cache key composition to include the SHA-256 of `cache_inputs` content (per plan.md). Implemented `compute_inference_cache_key(agent_version, prior_manifest, content_fetcher, fallback_paths=None)` in `cache_key.py` returning `sha256(agent_version | sha256(bundle))` where the bundle maps each sorted `cache_inputs` path to its content (missing files map to the sentinel `"<missing>"` so deletion invalidates). Empty `cache_inputs` is mixed with `"<empty-cache-inputs>"` rather than collapsing to `sha256(agent_version)`; first-run with `prior_manifest=None` requires non-empty `fallback_paths` (caller passes `env_spec_files`). Wired into `EnvCacheService.check_and_trigger` via `_inference_cache_suffix`, which appends a 12-char suffix to the existing `readme_sha`-derived key only when a prior manifest exists — preserves backward compatibility with all 71 existing env_cache tests. `local_path_fetcher` provides a sandboxed local-FS backend (rejects `..` traversal via realpath + `relative_to`). Phase 4's `forced_regen_cache_key(agent_version)` also lives here for the self-healing path.
- [x] T021 Integration test: edit a path *listed* in `cache_inputs` → cache invalidates. Edit a path *not* listed → cache reuses. Covered by `tests/integration/test_env_cache_inference_invalidation.py::test_edit_listed_cache_input_dispatches_bootstrap` (seal cache to match initial Gemfile content; no-change cycle skips; mutating Gemfile triggers exactly one dispatch) and `::test_edit_unlisted_path_reuses_cache` (seal; mutating README.md — not in `cache_inputs`, with stable mocked blob sha for the `env_spec_files` prefix — leaves dispatch list empty).
- [x] T022 Integration test: delete prior `services.json` → first-run fallback path engages. Covered by `::test_missing_prior_manifest_engages_fallback` which seals the cache with the bare `env_spec_files` prefix (no inference suffix, matching pre-063 format), asserts no dispatch on unchanged spec files, then drops a freshly-inferred `services.json` into the cache dir and asserts the next cycle dispatches because the tighter composed key (prefix + suffix) no longer matches the sealed bare-prefix key.

## Phase 4 — Self-healing on runtime health failure

- [x] T023 Propagate `services-health.sh` exit status from the performer back to `env_cache_service`. Performer-side: `agent/performer/src/performer/workspace.py` runs `services-health.sh` after `services-start.sh` succeeds via the new `_run_env_cache_health_check`, flipping module-level `_ENV_CACHE_HEALTH_FAILED` on non-zero exit; `consume_env_cache_health_failure()` reads-and-clears the flag. `_write_response` and `_perform_job` (stdio + HTTP-job chokepoints in `main.py`) drain the flag and stamp `env_cache_health_failed=True` on the outbound `PerformerResponse`. Wire protocol: `env_cache_health_failed: bool = False` added to both `PerformerResponse` and `ProtocolResponse`. Unit tests in `agent/performer/tests/unit/test_workspace.py::TestEnvCacheHealthCheck` cover passing/failing/missing-script paths and single-shot consumption.
- [x] T024 On runtime health failure, mark the env-cache stale and force the next bootstrap to bypass `cache_inputs` entirely. `EnvCacheState.runtime_health_failed: bool = False` added in `src/coordinare/models/env_cache.py`. `EnvCacheService.mark_runtime_health_failed(symphony_name, state)` flips the flag and logs `env_cache.runtime_health_failed`. `check_and_trigger` checks the flag *before* any SHA fetch and dispatches a forced regen using `forced_regen_cache_key(agent_version)` (time-nonce mixed, guaranteed cache miss), clearing the flag after dispatch. Daemon glue in `src/coordinare/graph/nodes/monitor_performer.py` routes `status.get("env_cache_health_failed")` from `service.check_status` into `mark_runtime_health_failed(state["current_symphony"], state)`. Unit tests in `tests/unit/services/test_env_cache_phase4.py` cover flag-set, unknown-symphony no-raise, dispatch-when-flagged, and no-dispatch-when-unflagged.
- [x] T025 Integration test in `tests/integration/test_env_cache_inference_invalidation.py::test_runtime_health_failure_self_heals`: seals env-cache to match current Gemfile content (no-flag cycle proves no dispatch), calls `mark_runtime_health_failed`, asserts next `check_and_trigger` dispatches with a 64-char forced-regen key distinct from the sealed key, flag clears, and `bootstrap_in_flight=True`. Demonstrates self-heal in one cycle without any spec-file or cache-input change.
