# Implementation Plan: Dashboard UX Redesign

**Branch**: `059-dashboard-ux` | **Date**: 2026-05-07 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/059-dashboard-ux/spec.md`

## Summary

Redesign the coordinare web dashboard's display layer for improved operator usability: introduce CSS design tokens (custom properties), consolidate scattered health indicators into a collapsible summary, enforce human-readable phase labels everywhere, add elapsed-time staleness flagging, render a meaningful idle state, improve navigation active-page indication, consolidate performer detail into a single view, and fix responsive overflow at 768px. All changes are confined to `src/coordinare/dashboard.py` and `tests/unit/test_dashboard.py` — no new backend endpoints or data model changes.

## Technical Context

**Language/Version**: Python 3.12+  
**Primary Dependencies**: FastAPI + Starlette (existing), vanilla JavaScript (inline), CSS custom properties (no build step)  
**Storage**: N/A — display layer only; all data from existing SSE snapshot  
**Testing**: pytest (unit tests for Python helpers); manual browser inspection for JS rendering  
**Target Platform**: Modern browser (Chromium, Firefox, Safari) served by the coordinare FastAPI daemon  
**Performance Goals**: No regression in SSE snapshot build time; dashboard initial render < 500ms on a local network  
**Constraints**: Single-file `dashboard.py` architecture preserved; no frontend build toolchain; dark colour scheme preserved; 768px minimum viewport  
**Scale/Scope**: Single-operator web dashboard; no concurrent user requirement beyond what FastAPI already handles

## Implementation Phases

### Phase A — CSS Design Token Foundation (FR-003, FR-009, FR-010)

Introduce the `:root` CSS custom properties block. Replace all hard-coded colour values in the `<style>` block and in JavaScript-generated inline `style=` attributes with `var(--color-*)` references.

**Scope**:
- Add `:root { --color-* }` token definitions (see `data-model.md`)
- Update all CSS rules in `<style>` to use `var()` references
- Update JS-generated inline `style=` attributes in `renderActiveWorkPanels`, `renderSubsystems`, the utilization table, and cycle history rendering

**Tests**: No new Python tests (CSS-only change). Verify visually that all panels render with correct colours.

**Acceptance**: No raw hex value remains in any CSS rule or JS-generated `style=` attribute. All panels visually match the existing dark theme.

---

### Phase B — Phase Label Enforcement (FR-003, SC-006)

Audit all JS rendering paths and ensure every raw `phase` or `performer_stage` string is passed through `formatPhaseLabel()` before insertion into the DOM.

**Scope**:
- `renderActiveWorkPanels`: wrap `session.phase` and `session.performer_stage`
- Cycle history table: wrap `entry.phase`
- Performer detail view: wrap phase display
- Add `formatPhaseLabel()` JS function (mirrors Python `format_phase_label()`)

**Python**: Extend unit tests for `format_phase_label()` to cover edge cases (empty string, single word, already-title-case, mixed separators).

**Acceptance**: No raw snake_case phase string visible in any dashboard panel.

---

### Phase C — Subsystem Health Summary Panel (FR-005, SC-001)

Replace the always-visible subsystem status table with a collapsible `<details>/<summary>` widget.

**Scope**:
- Rewrite `renderSubsystems()` JS function
- Summary line: `● All systems healthy` / `⚠ N systems degraded` / `✕ N systems unavailable`
- When healthy: `<details>` is closed by default; operator can expand to see the full table
- When degraded/unavailable: `<details>` is open by default; degraded rows highlighted with warning colour
- Add `computeOverallHealth(subsystems)` Python helper; expose result in snapshot for use in nav status dot too
- Add unit tests for `computeOverallHealth`

**Acceptance**: Health state readable in one line without expanding. Degraded detail auto-expanded.

---

### Phase D — Navigation Active-Page Indication (FR-004, FR-012, SC-002)

Fix navigation active-page highlighting for both SPA navigation and hard-load (direct URL).

**Scope**:
- Add `setActiveNav(path)` JS function that sets/clears `.nav-active` class and sets `aria-current="page"` on the matching link
- Call `setActiveNav(window.location.pathname)` on `DOMContentLoaded`
- Existing `navigate()` already calls nav updates on SPA transitions; refactor to use `setActiveNav()`
- Ensure hamburger menu closes after navigation on narrow viewports

**Acceptance**: Active nav link highlighted (blue underline) on both hard-load and SPA navigation. `aria-current="page"` set on active link.

---

### Phase E — Active Work and Awaiting Review Panel Redesign (FR-001, FR-002, FR-007, FR-008, SC-001, SC-008)

Redesign the Active Work and Awaiting Review panels with clearer visual hierarchy and all required data visible.

**Scope for Active Work panel** (sessions where `pr_url` is null):
- Card row shows: card title (linked to issue), phase label (human-readable), elapsed time, cost estimate
- Elapsed time: stale (> 30 min) renders with `⚠` prefix and `var(--color-degraded)` colour
- Cost: `"—"` when no session yet dispatched
- Clicking a row opens the consolidated performer detail (Phase F)

**Scope for Awaiting Review panel** (sessions where `pr_url` is non-null):
- Distinct visual treatment: amber/yellow left-border, header text "Awaiting Your Review"
- Shows: card title (linked to issue), PR link, time waiting, cost
- No click-to-detail required (read-only status)

**Python**: Add `is_session_stale(agent_dispatch_at_iso: str | None, threshold_minutes: int = 30) -> bool` helper with unit tests.

**Acceptance**: Both panels show required data without scroll. Stale cards visually flagged. Awaiting-review panel unmistakably distinct.

---

### Phase F — Consolidated Performer Detail View (FR-006, FR-014, SC-003)

Enrich the performer detail view to show phase, assigned card, elapsed time, cost, and log stream in one place.

**Scope**:
- When a row is clicked in the Active Work panel, find the matching session in `active_sessions`
- Render consolidated detail: phase label, card title + issue link, elapsed (with stale flag), cost, performer log stream (last 20 lines, live-updated)
- Reuse existing log-stream rendering; wrap in the new consolidated layout
- Back button returns to the Active Work panel list

**Acceptance**: Clicking a card row shows all 5 data points (phase, card, elapsed, cost, logs) in one view without additional navigation.

---

### Phase G — Idle State Panel (FR-011, SC-005)

Replace the collection of empty panels shown when `active_sessions.length === 0 && phase === "idle"` with a single informative idle panel.

**Scope**:
- Add `isIdle(snapshot)` guard in `applyState()`
- When idle: hide Active Work, Awaiting Review, and Performers cards; show `#idle-panel`
- Idle panel content: "Coordinare is idle", board summary (total cards, in-progress), last poll time (relative), assignee filter hint (if set), cycles completed today
- When not idle: show normal panels, hide `#idle-panel`

**Acceptance**: Idle state is a single informative panel, not multiple empty cards.

---

### Phase H — SSE Connection Status (FR-009, SC-007)

Improve the SSE connection status indicator to update promptly and communicate reconnection state.

**Scope**:
- Existing: `#nav-sse-dot` turns red on disconnect. Behaviour is correct; timing needs verification.
- Add `role="status" aria-live="polite"` to the nav status dot wrapper so screen readers announce changes
- Ensure the dot updates within 5 seconds of actual disconnect (EventSource `onerror` fires promptly; verify no delay from reconnect backoff)
- Add visible tooltip/title text: `"SSE connected"` / `"SSE disconnected — reconnecting"`

**Acceptance**: Status dot updates on disconnect; screen reader announces change; tooltip text is accurate.

---

### Phase I — Responsive Layout Fixes (FR-010, SC-004)

Fix overflow at 768px viewport width.

**Scope**:
- Wrap table containers on Symphonies page and Global Config page in `overflow-x: auto` divs
- Verify no fixed-width element in JS-generated HTML exceeds `100vw`
- Ensure navbar is fully visible at 768px without hamburger (current breakpoint is 767px — correct)

**Acceptance**: No horizontal scrollbar at 768px on any page. All primary panels readable.

---

### Phase J — Tests and Coverage (Constitution Principle II)

Ensure all new/modified Python helpers have unit tests and coverage does not drop below 90%.

**New tests**:
- `format_phase_label` edge cases (empty, already title, mixed separators)
- `render_performer_pool_widget` — idle, busy, excluded, mixed states
- `is_session_stale` — below threshold, at threshold, above threshold, null input
- `computeOverallHealth` equivalent (if extracted to Python) — all healthy, one degraded, one unavailable

**Acceptance**: `pytest --cov=coordinare --cov-fail-under=90` passes.
